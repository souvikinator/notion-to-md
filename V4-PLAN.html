1. Goal

  • Convert Notion content to Markdown, MDX, HTML, and any other format a renderer is written for.
  • Output is correct by default: v4 Markdown must be at least as good as v3.1.10.
  • Simple case is a few lines. Everything else is opt-in through plugins and handlers.
  • Core never touches disk or the network on its own, so it runs on serverless and edge.

Not goals for 4.0

  • Markdown → Notion, n8n node, database views/filters the API does not expose.
  • JSX and LaTeX renderers (possible later as community renderers).

2. Why rewrite, not patch

Problem in the v4 alphasCause
Markdown output worse than v3 (11 bugs reproduced: lists, toggles, code, tables, frontmatter)Each block transformer owns its own spacing, indentation and numbering; core joins with \n
Converter unsafe to reuse across pagesPipeline built once and cached with the first page's state
New format = copy a whole renderer (JSX copy is ~1,900 lines and dead)No shared document model between formats
Writes .notion-to-md/ to disk, needs fsMedia and page links built on manifests
Page links need a URL property in Notion plus a separate builder runLibrary converts one page at a time, never sees the whole site

3. Architecture

One reader, one tree, many writers (the Pandoc model).

   SOURCES                 TREE                 PLUGINS                RENDERERS
 (where blocks          (one typed,           (named hooks at        (tree in, string out)
  come from)            plain-JSON doc)        fixed stages)

┌──────────────┐                           ┌──────────────────┐     ┌────────────┐
│ notion()     │──┐    ┌──────────────┐    │ downloadMedia()  │  ┌─▶│ markdown() │
├──────────────┤  │    │  normalize   │    │ media(fn)        │  │  ├────────────┤
│ fromBlocks() │──┼───▶│  Notion →    │───▶│ pageLinks(fn)    │──┼─▶│ mdx()      │
├──────────────┤  │    │  Document    │    │ frontmatter()    │  │  ├────────────┤
│ cached()     │──┘    └──────────────┘    │ user plugins     │  └─▶│ html()     │
└──────────────┘                           └──────────────────┘     └─────┬──────┘
                                                                          ▼
                              Page { content, properties, assets, links, tree, warnings }
                                                                          │
                             node helpers (outside core): writeFile · downloadMedia · fileCache

Flow of one convert(id) (src/core/convert.ts)

1. source.page(id) + source.blocks(id)  in parallel    (network, concurrency pool)
2. normalize(page, blocks)  → Document                 (pure)
3. plugin.transform(tree)   for each plugin            (tree edits)
4. plugin.resolveAsset      for every file  ┐ in parallel; first plugin returning a URL wins
   plugin.resolveLink       for every link  ┘
5. renderer.render(tree)    → string                   (pure)
6. plugin.result(page)      for each plugin            (e.g. frontmatter)
State lives only inside one convert() call; the instance holds config. Tested: three pages converted at once on one instance give correct, separate output.

4. The pieces

4.1 Source

interface Source {
  page(id): Promise<RawPage>              // properties, url, icon
  blocks(id): Promise<RawBlock[]>         // nested children already fetched
  query?(databaseId, query?): AsyncIterable<PageObjectResponse>
}
  • notion(client, { concurrency = 3, databases = true }) — SDK v5, data sources, pool of N requests in flight. Retries on 429 are the SDK client's (it honours Retry-After).
  • fromBlocks({ blocks, page? }) — offline conversion of saved JSON (discussion #136).
  • Extra data a block needs is attached by the source: children, database rows, linked page title, or error when Notion denies access.

4.2 Document tree (src/tree/types.ts)

Document { id, title, url, icon?, properties, children: Block[] }

Blocks                                         Inline
──────                                         ──────
paragraph, heading(level 1–4, toggleable)      text { value, marks }   marks: bold italic strikethrough
list(kind, start, style) > listItem(checked?)                                  underline code color
quote, callout(icon), toggle                   link { url, children }
code(language, value, caption)                 pageLink { pageId, blockId?, url, children }
equation, divider                              inlineEquation { value }
table { columnHeader, rowHeader, rows }        break
columns > column
media { kind, url, hosted, name, caption }     every text block: { content: Inline[], children: Block[] }
embed { kind, url, caption }
pageRef { pageId, title, url }
database { title, url, columns, rows }
tableOfContents, unknown { notionType }
  • inlineContent(), blockChildren(), childNodes() in visit.ts are the only code that knows where children live. Renderers, visit and URL resolution all use them.

4.3 Plugins (src/core/types.ts)

interface Plugin {
  name: string
  transform?(document, context): void | Promise<void>
  resolveAsset?(asset, context): string | undefined | Promise<…>   // first URL wins
  resolveLink?(link, context): string | undefined | Promise<…>     // first URL wins
  result?(page, context): Page | undefined | Promise<…>
}
context = { warn(message), site: Map<pageId, SitePage> }

4.4 Renderers

markdown({ escape?: boolean, handlers?: { [nodeType]: (node, { content, children, fallback }) => string } })
mdx(...)  html({ handlers })
  • A handler replaces a node type's output everywhere, including nested.
  • markdown() builds mdast and serializes with mdast-util-to-markdown + GFM. Handler output is placed as raw nodes, so the serializer still handles list indentation and blank lines around it.
  • mdx() = same converter with the MDX dialect injected (mdast-util-mdx + escaping of { } <).

5. Public API (as built)

import { notionToMd, notion } from 'notion-to-md'
import { markdown } from 'notion-to-md/markdown'

// simplest
const n2m = notionToMd({ source: notion(client), renderer: markdown() })
const { content } = await n2m.convert(pageId)

// blog
import { mdx } from 'notion-to-md/mdx'
import { pageLinks, frontmatter } from 'notion-to-md/plugins'
import { downloadMedia, writeFile } from 'notion-to-md/node'

const blog = notionToMd({
  source: notion(client),
  renderer: mdx(),
  plugins: [
    downloadMedia({ dir: './public/img', publicPath: '/img' }),
    pageLinks((link, { site }) => {
      const slug = site.get(link.pageId)?.properties.Slug
      return typeof slug === 'string' ? `/blog/${slug}` : undefined
    }),
    frontmatter({ rename: { Name: 'title' } }),
  ],
})
for await (const page of blog.pages(databaseId))
  await writeFile(page, `content/${String(page.properties.Slug)}.mdx`)

7. Implementation decisions (made while building — please review)

Calls I made on my own tonight, based on our discussion, the SDK, and tests. Each is easy to change.
#DecisionWhy / trade-off
Runtime and tooling
D18Fetching uses a pool that keeps N requests in flight (slot handed straight to the next task); retries are left to the SDK clientWaves of 3 waited for the slowest request. SDK v5 already retries 429/5xx with Retry-After, so a second retry layer would double-wait. Test: 12 toggles, concurrency 4 → 4 in flight the whole time.
D19Node ≥ 22, @notionhq/client ≥ 5 as peer, TypeScript 6.0SDK v5.31 itself needs Node 22; Node 20 is end-of-life. TS 7 (native) is out, but typescript-eslint supports only < 6.1, so lint would break.
D20Source has page() and blocks() separatelypages() already has each row's page object from the database query, so it only fetches blocks: one call saved per page.
D21The renderer is required (no default)A default markdown() would ship the Markdown serializer to HTML-only users. One extra import keeps tree-shaking real.
D22ESM + CJS builds; ESM keeps deps external, CJS bundles the ESM-only mdast packagesCJS users (and Jest) can require() it; ESM bundlers dedupe mdast. Checked with publint, are-the-types-wrong and real require/import of the build.
D23Lint guardrails: strictTypeChecked + stylistic; node:* only in src/node; core/tree/source cannot import render/plugins/node; complexity ≤ 15Keeps the architecture from drifting. Flat "map every Notion type" switches are exempt with a stated reason.
Markdown output
D24Escaping of Notion text is off by default (markdown({ escape: true }) turns it on); pipes in tables and MDX's { } < are always escapedSame call as v3.1.10 (#176): people type Markdown in Notion on purpose. Only escapes that would break the document's structure are forced.
D25Spaces at the edge of bold/italic/etc. move outside the marker; neighbouring pieces with the same formatting merge**bold ** is not bold in Markdown (#164). Merging gives **very *bold* text**, not **very *****bold***.
D26Bold next to punctuation (#174) is left to mdast-util-to-markdown, which writes a character reference (e.g. fo&#x6F;**"bar"**)Valid in every CommonMark parser (tested). Trade-off: visible in the raw file. Alternative was falling back to <strong>.
D27Line breaks: \ + newline in text, <br /> inside table cellsv3 wrote a bare newline, which Markdown joins into one line. A \ break is the CommonMark hard break and survives editors that trim trailing spaces.
D28Notion background colours become <mark>; text colours are dropped in Markdown; HTML keeps both as class="color-…"#145. Same approach as underline → <u>. Markdown has no colour syntax.
D29Toggles and toggleable headings → <details><summary>; the summary is rendered by the HTML renderer; heading stays as <h2> inside the summaryWorks on GitHub and in MDX (tested by compiling). Reuses the HTML inline renderer instead of a second implementation. Users can override toggle to flatten.
D30Callouts → block quote starting with the emojiRenders everywhere. GitHub alerts (> [!NOTE]) need guessing a type from a colour; better as a user handler.
D31Tables without a header row get an empty header rowGFM tables require a header (#172). No fake "Column 1" text.
D32Tables are written compact (| a | b |), not padded to align columnsPadding makes every edit rewrite the whole table in diffs.
D33Equations as $…$ and $$…$$ in Markdown and MDXThe common convention. MDX with braces in TeX needs remark-math (tested with it); without it TeX is unreadable anyway.
D34Images use the caption as alt text; other files become links labelled with the caption, else the file nameSame as v3 for images. File name comes from Notion or the URL path, set once in the tree.
D35Content nested under a paragraph (Notion indent) is written after it, not indentedIndenting a paragraph in Markdown turns it into a code block. Nested content under list items, quotes, callouts and toggles stays inside them (#162).
D36In Markdown, a listItem handler returns the item body (the list adds the marker). A text handler gets each text on its own (no merging with neighbours); its fallback() keeps the formatting. A list handler's children() is the items as one list.Lists must stay lists. A text handler must be able to change words without losing bold/italic (bug found in review).
Content handling
D37Child pages and "link to page" become link blocks; the source fetches a linked page's title (1 call per link)#88/#106. Without the title, links read "Untitled".
D38Databases inside a page: rows fetched by default (first data source), rendered as a table whose title cell links to the row page (resolved by pageLinks)#22. Multi-source databases only show the first source for now.
D39Extra data Notion refuses (database or synced original not shared) → warning, conversion continues#158. Only "not found / restricted / validation" errors; other errors still throw.
D40Synced copies read their original; tab, template, meeting notes are flattened into their children; breadcrumbs dropped; table of contents not rendered yetNew SDK v5 block types handled; nothing disappears silently (unsupported → unknown node + warning).
D41Tree nodes keep the Notion id only, not a copy of the raw blockPlan said "keep the original block"; that doubles memory and JSON size. Raw data is still available from the source.
D42Page properties become plain values: dates as ISO strings, ranges as ISO intervals (start/end), people as names, files as { name, url, hosted }One predictable type per property, ready for frontmatter.
D43Frontmatter writes YAML using JSON values; no YAML dependency; nothing is added when there are no fieldsJSON strings, arrays and numbers are valid YAML. Quotes and colons are escaped correctly (tested).
D44downloadMedia names files by a hash of the Notion file path; skips files that exist; streams to a temp file then renames; a failed download warns and keeps the URL; external files untouched by defaultNotion re-signs URLs on every request but the path is stable, so no manifest is needed (#163, #133). Trade-off: no automatic cleanup of removed files; page.assets lists what is used.
D45downloadMedia and writeFile live in notion-to-md/node; media(fn) and pageLinks(fn) are generic plugins in notion-to-md/pluginsEverything touching fs is in one entry, so the rest runs on edge runtimes.
D46Noted: SDK v5 has pages.retrieveMarkdown (Notion's own Markdown export)Our value is formats, plugins, media, links and control of output. Worth a line in the README.
After the independent review
D47The Notion → tree mapping lives in src/normalize; src/tree only holds the neutral model and helpersRenderers and plugins no longer import Notion-specific code. Lint enforces the boundary.
D48Ids are normalized once in core; convert() and pages() also accept a Notion linkSources get one id format. Users can paste a page URL.
D49Block, text, mention and property types newer than the installed client never crash: blocks become unknown + warning, text keeps its plain text, properties become nullThe peer range is >=5, so the API can send types our build doesn't know.
D50cached(source, store) keeps one entry per page and reuses blocks while the page's last_edited_time is unchanged. fileCache(dir) (node) stores one JSON file per pageA hit costs one request instead of one per block with children. Trade-off: synced blocks, database rows and linked titles refresh only when the page itself is edited; in pages() a miss costs one extra request.
D51Embedded databases read rows from every data source; columns come from the firstRows were silently missing for multi-source databases.
D52Code captions render under the code (paragraph in Markdown, <figcaption> in HTML)They were dropped.
D53Line breaks at the start or end of a block's text are droppedShift+Enter at the end of a line left a stray \.
D54MDX output assumes the site uses remark-gfm (tables, task lists, strikethrough) and remark-math (equations)Same as any MDX site with these features. Tests compile and render MDX with both.
D55fromBlocks throws when it cannot find a page idAn empty id leaked into asset ids and page.id.
From the blog posts and closed issues
D57notion(client, { comments: true }) fetches page and block comments (off by default: one request per block). footnotes() turns block comments into GFM footnotes; page comments stay on tree.commentsBlog "comments as footnotes", #143. A missing "read comments" capability is a warning.
D58Every node has data. Async work (fetch a PDF, parse it) happens in a plugin's transform and is stored on node.data; handlers stay synchronous and read itBlog "documents". Same pattern as unified/mdast. Keeps rendering simple and fast.
D59MDX handlers get addImport(); imports are collected per render and written at the top (after frontmatter)Blog PDFViewer and alpha.5 StatusBadge examples.
D60Frontmatter transform is keyed by the output field (after rename), gets the value and the page, and can add new fields; defaults fill missing or empty fields; a failing transform warns and keeps the valueAlpha keyed transforms by property and couldn't add fields; the blog's slug example needed that.
D61downloadMedia({ publicPath }) also takes a function; include picks files by where they appear (block, page_cover, page_property, database_property)Alpha's transformPath and enableFor (#133).
D62The page cover is part of the tree and handled like any other file#133 asked for covers to be downloaded.
D63notion(client, { databaseQueries }) filters and sorts databases inside pages, by database idAlpha.5 configureDatabase.
D64Spaces and line breaks at the start or end of a block's text are dropped (not inside inline code)Notion never shows them; they leaked into summaries and headings.
D65With escape: true, bare URLs are never escapedSame as v3.1.10 (#176): a backslash inside a URL stops GitHub from linking it.
D66Inline equations are trimmed ($ x $ → $x$); code drops leading blank lines and trailing whitespaceAlpha.7 #160 and v3.1.10 #177.
D67default_background colour means no colourIt was being written as a highlight.
D68Nested lists indent by the marker width (2 spaces for -, 3 for 1.), the CommonMark and Prettier styleAlpha used 4 spaces (#127). Both render the same; this is what mdast-util-to-markdown writes. Change with listItemIndent if you prefer 4.
D69Links on *.notion.site and workspace subdomains are treated as links to Notion pagesAlpha excluded them; they are public Notion pages, so they should resolve too.
Simplification review
D70A text handler changes the words only, in every renderer; bold, italic, code and the rest are applied around what it returns. Replaces the second half of D36Removed a second code path in the Markdown renderer and made Markdown and HTML behave the same.
D71Renderers get only the document (render(document)); the unused render context is goneNo built-in renderer used it. Adding an argument later is not a breaking change.
D72One edge-whitespace function (tree/whitespace.ts) used by the normalizer and the Markdown renderer; one way to describe a file in core/resolve.tsThe same trimming logic existed twice; file info was built three times.
D73Kept on purpose: our own pagination and "is full object" checks in notion(), although the SDK has helpersThe SDK is CommonJS. Importing code (not just types) from it would pull the whole client into every bundle, including for fromBlocks()-only users.
D56Open: a page's own URL is Notion's slug URL, while links to pages use the id form (notion.so/<id>)We only know a page's slug URL when we fetched that page. Plugins should compare by pageId, not URL. Revisit if it confuses users.
