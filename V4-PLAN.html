1. Goal

  • Convert Notion content to Markdown, MDX, HTML, and any other format a renderer is written for.
  • Output is correct by default: v4 Markdown must be at least as good as v3.1.10.
  • Simple case is two lines. Everything else is opt-in through plugins and handlers.
  • Core never touches disk or the network on its own, so it runs on serverless and edge.

Not goals for 4.0

  • Markdown → Notion, n8n node, database views/filters the API does not expose.
  • JSX and LaTeX renderers (possible later as community renderers).

2. Why rewrite, not patch

Problem in the v4 alphasCause
Markdown output worse than v3 (11 bugs reproduced: lists, toggles, code, tables, frontmatter)Each block transformer owns its own spacing, indentation and numbering; core joins with \n
Converter unsafe to reuse across pagesPipeline built once and cached with the first page's state
New format = copy a whole renderer (JSX copy is ~1,900 lines and dead)No shared document model between formats
Writes .notion-to-md/ to disk, needs fsMedia and page links built on manifests
Page links need a URL property in Notion plus a separate builder runLibrary converts one page at a time, never sees the whole site
Fetches every nested sub-page; slow rate limiter; no retryFetcher follows has_children blindly

3. Architecture

One reader, one tree, many writers (the Pandoc model).

   SOURCES                 TREE                 PLUGINS                RENDERERS
 (where blocks          (one typed,           (tree in, tree        (tree in, string out)
  come from)            plain-JSON doc)        out; named hooks)

┌──────────────┐                           ┌──────────────────┐     ┌────────────┐
│ notion()     │──┐                        │ media.*()        │  ┌─▶│ markdown() │
├──────────────┤  │    ┌──────────────┐    │ pageLinks()      │  │  ├────────────┤
│ cached()     │──┼───▶│  normalize   │───▶│ frontmatter()    │──┼─▶│ mdx()      │
├──────────────┤  │    │  Notion →    │    │ footnotes()      │  │  ├────────────┤
│ fromBlocks() │──┘    │  Document    │    │ user plugins     │  └─▶│ html()     │
└──────────────┘       └──────────────┘    └──────────────────┘     └─────┬──────┘
                                                                          ▼
                                    { content, data, assets, links, tree, warnings }
                                                                          │
                                         helpers (outside core): writeFile · download · upload

Flow of one convert(id)

1. source.page(id)        → raw Notion blocks + properties         (network, concurrent, retried)
2. normalize(raw)         → Document tree                          (pure)
3. plugins.transform      → Document tree                          (tree edits)
4. plugins.resolveAsset   → url for every asset node               (download / upload / keep)
   plugins.resolveLink    → url for every pageRef node
5. renderer.render(tree)  → string                                 (pure; core owns layout)
6. plugins.result         → final { content, data, assets, ... }
State lives only inside one convert() call. The instance holds config. Steps 2 and 5 are pure functions, so they are snapshot-testable without Notion.

4. The pieces

4.1 Source

interface Source {
  page(id): Promise<RawPage>          // blocks (nested) + properties
  list?(databaseId, query?): AsyncIterable<RawPageMeta>
}
  • notion(client, { concurrency, childPages }) — SDK v5, concurrency limit, retry on 429 with Retry-After.
  • cached(source, store) — wraps any source; key = page id + last_edited_time.
  • fromBlocks(json) — offline conversion of saved blocks.
  • Child pages: not fetched by default. They become pageRef nodes.

4.2 Document tree

Our own tree, shaped like Notion. Plain JSON.

Document { id, data (properties), children: Block[] }

Block nodes                                Inline nodes
───────────                                ────────────
paragraph   heading(level, toggle?)        text { value, marks[] }
list(ordered) > listItem(checked?)         marks: bold italic strike underline code color
quote       callout(icon, color)           link { url, children }
toggle      code(lang, value)              mention { kind: page|user|date|…, ref }
table > tableRow > tableCell               equation { value }
columns > column                           pageRef { pageId, blockId?, children }
image/video/file/pdf → asset { kind, source, caption }
equation    divider    embed/bookmark { url, caption }
database { schema, rows }    pageRef (child page, link to page)
raw { notionType, block }   ← anything unknown, never dropped silently
  • Lists are grouped into list containers at normalize time, so numbering and nesting are structural.
  • Every node keeps id and notion (original block) for escape hatches.
  • asset and pageRef are explicit nodes, so plugins find them with one visit.

4.3 Plugins

interface Plugin {
  name: string
  transform?(tree, ctx): Document | void
  resolveAsset?(asset, ctx): string | undefined   // first plugin to return wins
  resolveLink?(ref, ctx): string | undefined      // first plugin to return wins
  result?(page, ctx): Page | void
}
  • Stage is fixed by the hook name. Array order only matters between plugins using the same hook.
  • Built-ins: media.download(dir), media.upload(fn), media.inline(), pageLinks(fn), frontmatter(opts), footnotes().
  • ctx gives: visit(tree, type, fn), warn(), site (all pages, when run through pages()).

4.4 Renderers

markdown({ handlers: {
  callout: (node, ctx) => `:::note\n${ctx.children()}\n:::`,
}})
  • A renderer is a map of node type → (node, ctx) => string, plus the format's escape and join rules.
  • Core owns blank lines, indentation, numbering, escaping. Handlers cannot break layout.
  • markdown(): tree → mdast → mdast-util-to-markdown (bundled). Custom handlers emit raw text nodes.
  • mdx() = markdown() + overrides + import collection. html() is a second handler set.
  • Unknown node type → warning + fallback text, never a crash.

4.5 Result and helpers

interface Page {
  id, content: string, data: Record<string, unknown>,   // data = simplified properties
  assets: Asset[], links: PageRef[], tree: Document, warnings: Warning[]
}
  • Helpers live under notion-to-md/node: writeFile(page, path, { frontmatter }). Only helpers and media.download use fs.
  • Errors: fetch errors throw. Per-node problems go to warnings; strict: true turns them into throws.

4.6 Many pages

for await (const page of n2m.pages(databaseId, { filter, sorts })) { ... }
  • Lists the pages first, so resolveLink knows every page (ctx.site). No builder pre-pass, no URL property in Notion.
  • Streams one page at a time; memory stays flat.
  • Child pages can be emitted as their own Page with a parent id (folder trees).

5. Public API

import { notionToMd, notion } from 'notion-to-md'
import { mdx } from 'notion-to-md/mdx'
import { media, pageLinks, frontmatter } from 'notion-to-md/plugins'
import { writeFile } from 'notion-to-md/node'

// simplest
const { content } = await notionToMd({ source: notion(client) }).convert(pageId)

// blog
const n2m = notionToMd({
  source: notion(client),
  plugins: [
    media.download('./public/img', { publicPath: '/img' }),
    pageLinks((p) => `/blog/${p.data.slug}`),
    frontmatter({ include: ['title', 'date', 'tags'] }),
  ],
  renderer: mdx({ handlers: { callout } }),
})
for await (const page of n2m.pages(databaseId))
  await writeFile(page, `content/${page.data.slug}.mdx`)

7. Package and layout

exports                         src/
───────                         ────
notion-to-md            core    index.ts            notionToMd, types
notion-to-md/markdown           source/             notion, cached, fromBlocks
notion-to-md/mdx                tree/               node types, normalize, visit
notion-to-md/html               plugins/            media, pageLinks, frontmatter, footnotes
notion-to-md/plugins            render/core.ts      layout, context, fallback
notion-to-md/node       fs      render/markdown/  render/mdx/  render/html/
                                node/               writeFile
                                tests/              fixtures/, snapshots, parser round-trips
  • ESM + CJS builds with correct exports conditions (tsup). mdast-util-to-markdown bundled.
  • Runtime deps: none beyond what is bundled. Built-in fetch. Peer: @notionhq/client.
  • Old alpha code is removed from the branch, not kept alongside.

8. Testing

  • Fixtures: recorded Notion JSON for every block type and nesting case.
  • Normalize: fixture → tree snapshots.
  • Render: tree → output snapshots, plus parse the Markdown with a real parser and compare text (catches broken layout).
  • Regression list: every bug in the issue map below gets a named test.
  • v3 parity: same fixtures through v3.1.10; diffs must be reviewed and intentional.
  • End to end: mock source; one live test page behind an env token.

9. Milestones

M0 — Setup

  • Clear old alpha source; keep tooling (vitest, tsup, eslint)
  • Fix package exports, engines, remove unused deps
  • Record fixture set from a real test workspace
Done when: empty package builds and CI is green.

M1 — Tree and normalizer

  • Node types (block + inline)
  • Normalize: all block types, list grouping, rich text → marks
  • visit helper; raw node for unknown blocks
Done when: every fixture has a reviewed tree snapshot.

M2 — Markdown renderer

  • Render core: context, children(), fallback, warnings
  • Tree → mdast → Markdown; custom handlers
  • Regression tests for all listed bugs; v3 parity run
Done when: output beats v3.1.10 on every fixture. Go/no-go point for the design.

M3 — Notion source

  • notion() on SDK v5: blocks, properties, databases/data sources
  • Concurrency limit, 429 retry, childPages option
  • fromBlocks(), cached()
  • notionToMd().convert() end to end
Done when: live test page converts; publish 4.0.0-beta.1.

M4 — Plugins

  • Hook runner (transform, resolveAsset, resolveLink, result)
  • media.download / upload / inline, including files in properties
  • pageLinks, frontmatter, footnotes
  • writeFile helper
Done when: the blog example in section 5 runs.

M5 — Many pages and more formats

  • n2m.pages() with ctx.site; child pages as separate pages
  • mdx(), html()
  • Database block rendering (table)
Done when: a full database converts with working internal links; publish 4.0.0-rc.1.

M6 — Docs and release

  • Docs: getting started, plugins, handlers, writing a renderer
  • Migration guides: v3 → v4, alpha → v4
  • README on master points to v4; update #112; close mapped issues
  • Publish 4.0.0 as latest
Done when: 4.0.0 is on npm and v3 is marked maintenance-only.

11. Release and migration

  • Tags: 4.0.0-beta.x (npm tag beta) from M3 → rc at M5 → 4.0.0 as latest at M6.
  • Alpha users: the alpha API is not kept. One migration page maps old calls to new ones.
  • v3 users: v3 stays on master for urgent fixes only. Migration table:
    v3v4
    new NotionToMarkdown({ notionClient })notionToMd({ source: notion(client) })
    pageToMarkdown + toMarkdownStringconvert(id) → page.content
    setCustomTransformer(type, fn)markdown({ handlers: { type: fn } })
    separateChildPagepages() / childPages option
  • Branching: rewrite lands on a v4 branch through small PRs per milestone; merges to master at release.
